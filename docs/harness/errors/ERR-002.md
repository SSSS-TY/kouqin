# ERR-002: `git push` 被 GitHub 以 GH007 拒绝（提交作者邮箱属于受保护的私有邮箱）

- **发现时间**: 2026-09-25
- **发现者**: User（执行 `git push` 时）
- **状态**: Unresolved（等待用户执行修复并确认推送成功）
- **影响范围**: 版本控制推送链路；代码文件本身不受影响
- **关联任务**: 仓库初始化与首次推送
- **关联决策**: ADR-004（public 仓库 + 个人非商业许可）

## 错误现象

```text
remote: error: GH007: Your push would publish a private email address.
remote: You can make your email public or disable this protection by visiting:
remote: https://github.com/settings/emails
To github.com:SSSS-TY/kouqin.git
 ! [remote rejected] main -> main (push declined due to email privacy restrictions)
error: failed to push some refs to 'github.com:SSSS-TY/kouqin.git'
```

推送对象只有 5 个对象（1 个提交、1 个 blob、3 个 tree），说明**先前提交已成功推送到远端**，
被拒的只是最新那个提交。

## 复现步骤

1. GitHub 账号开启 Settings → Emails → "Keep my email addresses private"；
2. `git config user.email` 仍为真实邮箱（`jimotang0@gmail.com`）；
3. 提交任意改动后 `git push`；
4. GitHub 拒绝推送（GH007）。

## 分析过程

- **假设 1**: GitHub 的邮箱隐私保护会拒绝作者邮箱等于该账号受保护邮箱的推送。
  - **验证方法**: 报错信息直接指向 `https://github.com/settings/emails`，并写明
    "make your email public or disable this protection"。
  - **结果**: 成立。
- **贡献因素**: Agent 在上一步建议用户开启该隐私开关，但**未同时提醒**把 git 的 `user.email`
  改为 GitHub 提供的 noreply 地址，导致两者组合产生必然失败。

## 已尝试方案

### 尝试 1

- **修改或操作**: 无（首次遇到，尚未尝试修复）。
- **结果**: —
- **新证据**: 报错文本已给出两条可行路径（公开邮箱 / 关闭保护）。

## 根本原因

GitHub 的 "Keep my email addresses private" 与本地 `user.email`（真实邮箱）冲突：
推送会暴露受保护邮箱，因此被服务端拒绝。

## 修复方案

任选其一：

1. **改用 noreply 邮箱并重写提交**（推荐，顺带抹掉已公开的真实邮箱）：

   ```powershell
   git config --global user.email "<GitHub 设置页给出的 noreply 地址>"
   git rebase --root --exec "git commit --amend --no-edit --reset-author"
   git push --force-with-lease origin main
   ```

2. **让邮箱公开**：关闭该隐私保护开关后直接 `git push`。

3. **删库重建**：仓库只有一两个提交时最省事，但需要重新建 public 仓库。

## 验证方法

```powershell
git log --oneline --format="%h  %an <%ae>  %s"   # 全部应为 noreply 地址
git push --force-with-lease origin main
git status --short                              # 应为空
```

预期结果：推送成功，GitHub 仓库页面的提交作者显示 noreply 地址。

## 当前阻塞

需用户在本地终端执行上述修复（Agent 不执行 git 写操作，且沙盒内 `git init` 会破坏环境，见 ERR-001）。
